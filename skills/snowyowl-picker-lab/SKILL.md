# 雪鴞選股實作室

先定位包含 `stock-picker/presets.json` 的學生專案，讀 AGENTS.md、docs/stock-picker-workbook.md、docs/stock-picker-source-audit.md。不要寫死老師電腦路徑。

1. 問清使用者的週期與要解決的投資問題。若已提供，就直接沿用。
2. 讀指定卡片的原條件、教學定義、status與缺口。分成可見、明確、未知、使用者新增。來源頁面不是隱藏公式證據。
3. 本機重跑只用已有雪鴞環境。`build_data.py --env <本機.env>`由登入助手讀帳密，AI不讀檔、不顯示、不提交。原始資料只留`.local`。
4. 先記錄原版本、資料日、範圍、候選數和一筆手動核對。公開demo只有16檔；未報告資料不補零，營收財報會計期間不是公告日。
5. 修改前寫下假設，保留原版本。畫面改app.js/style.css，規則改rules.py，資料改build_data.py，卡片規格改presets.json。每次只改與本次假設有關的一項。
6. 規則變更跑test_rules.py，再用實際資料核對一個符合、一個不符合與一個缺資料案例。畫面變更實際操作並檢查手機版。不要只說「測試成功」。
7. 候選篩選與買賣規則分開。若要回測，先補完整進出場、部位、成本、公告時間與股票範圍，再在strategies/<新名稱>/使用雪鴞api.bt；不能從每日最新快照反推當年的可得資料。
8. 每次產出Markdown：假設、檔案、規格版本、證據、結果與限制、下一步。結果不好也保存。未驗證不標完成。

中斷寫 `resume.md`：已完成檔案與證據、失敗原因、缺口、下一個可執行步驟。進度圖是專案狀態，不代表AI正在背景工作。請勿把帳密、供應商大量原始資料或學生群組截圖放到公開儲存庫。
