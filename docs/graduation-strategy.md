# 畢業禮物：台積電法說會事件策略

上一堂學會用 AI，這一堂學會帶 AI 把事情做完。

## 策略框架

標的固定 **2330 台積電**；只取台積電官方公告的**季報法說會**，不混投資機構說明會。確認事件日期、時區、交易日及會議時間在收盤後。日期來源：[台積電官方行事曆](https://investor.tsmc.com/chinese/financial-calendar)。

研究假設：市場對法說會的預期是否在當日收盤前形成可交易現象？這是假設，並非已證实因果。

流程：前一日準備 → 法說當日09:00開盤價模型做多 → 13:30收盤價模型退出 → 盤後記錄。不留到法說之後，不抱隔夜。

原研究沒有額外停損、停利或篩選；加入這些條件就是新版本，需另測。金額由個人風險預算決定，先用模擬。普通交易開收盤模型不等於零股成交價；無法按計畫成交時記錄偏差，不假裝成交。研究專案不自動下單。

## 原研究結果：待價格與事件日期核對

|既有資料|期間|扣成本後勝率|平均逐次淨報酬|
|---|---|---|---|
|小時K價格明細|2023/10/19～2026/07/16|10 / 12 = **83.3%**|+0.528%|
|日K事件明細|2020/10/14～2026/07/16|13 / 24 = **54.2%**|+0.123%|

**同12個事件日期，有9次開盤到收盤報酬差異超過0.01個百分點。83.3%尚未完成價格一致性驗證，不能當成已驗證的高勝率。** 這不只是樣本期間不同；也不能挑較高的檔案當作真實績效。

成本模型：手續費每邊0.0285%＋當沖稅0.15%，合計0.207%；未含滑價、最低費與實際成交偏差。勝利定義是扣完成本後淨報酬>0。費率與當沖資格實作前另確認。

資料出自老師WorkBuddy的 `snowyowl_orb/output/tsmc_conf_prices.csv` 與 `tsmc_conf_daily.csv`；原腳本使用yfinance，**不是雪鴞api.bt回測**。本次只重算既有CSV，未重新取行情、未重跑引擎。來源雜湊與差異詳見 [數據核對](graduation-strategy-audit.json)。日K首筆事件日期也須再查官方歷史資料；兩份數據尚未完整驗收，沒有獨立樣本外證據。

## 交給你的 AI：直接複製

```text
請依台積電季報法說會當日開盤做多、當日收盤退出的規格，
先做研究專案，不要自動下單。
建立六個模塊：事件日期、行情、交易規則、成本、報告、經驗筆記；
畫出工作流與進度圖，各步驟寫輸入、輸出與驗收。
先確認官方季報法說會日期，不混機構說明會。
核對原資料同事件的小時K與日K差異，含時區、還原口徑與K線時間。
83.3%是未完成價格核對的12次樣本，不是已驗證勝率。
正式新回測用雪鴞api.bt，先確認可用資料與事件表；
缺資料記阻礙，不默默換資料源，不借用舊勝率當新結果。
先把每次事件的進場、出場、成本與可成交性對齊，
再輸出逐筆交易、逐日權益、回撤與一般日對照。
原版核對完成後，寫一個修改假設，一次只改一項條件，
同日期同成本比較，另留未看過的事件驗證。
每次成功、失敗、原因都存Obsidian Markdown，留下續工單。
最後接Telegram提醒與復盤，不要把通知當作自動交易。
```

## 看到結果後如何修改

P：同一日期價格為何不一致？先提出問題。
D：請AI核對官方事件表、時區、K線對齊、價格口徑與成交模型。
C：同一批日期、同成本比較，保存差異；資料尚未核對就不宣稱獲利。
A：原版確認後再試「12:00進場」等單項假設，另驗未看過事件。

注意：12:00→13:30與09:00→13:30是不同策略，不能沿用83.3%。原研究12:00版本為7/12淨利正（58.3%），同樣有待行情驗證。

完成的畢業成果：一份有規格、有資料來源、有核對紀錄、能接著修改的策略專案。
